# CI/CD Plan — Vibely

> Дата: 2026-09-17
> Инфра: VPS + Docker Compose
> CI: GitHub Actions

---

## Стратегия веток

```
feature/*  ──┐
refactor/* ──┼──→  PR → main  ──→  staging.vibely.com  (авто)
fix/*      ──┘                             │
                                    merge main → release
                                           │
                                     vibely.com  (авто)
```

| Ветка | Триггер CI | Деплой |
|-------|-----------|--------|
| `feature/*`, `refactor/*`, `fix/*` | lint + build на каждый push | нет |
| PR → `main` | lint + build (блокирует merge при ошибке) | нет |
| push в `main` | lint + build → деплой | staging.vibely.com |
| push в `release` | деплой | vibely.com |

---

## Структура файлов

```
.github/
└── workflows/
    ├── ci.yml              # lint + build — PR и feature-ветки
    ├── deploy-staging.yml  # деплой на staging при пуше в main
    └── deploy-prod.yml     # деплой в прод при пуше в release
```

---

## Workflow 1 — `ci.yml`

**Триггер:** push в `feature/**`, `refactor/**`, `fix/**` + PR в `main`

**Джобы:**

```
frontend-lint  ─┐
backend-lint   ─┼─→  (параллельно, fail-fast)
ai-lint        ─┘
     │
frontend-build ─┐
backend-build  ─┘  (параллельно, только если lint прошёл)
```

Шаги каждой джобы:
- `frontend-lint`: `npm ci` → `npm run lint` (eslint + tsc --noEmit)
- `backend-lint`: `npm ci` → `npm run lint` + `npx tsc --noEmit`
- `ai-lint`: `pip install ruff` → `ruff check ai/`
- `frontend-build`: `npm ci` → `npm run build`
- `backend-build`: `npm ci` → `npm run build`

---

## Workflow 2 — `deploy-staging.yml`

**Триггер:** push в `main`

**Шаги:**
1. Запустить те же джобы ci.yml (или потребовать чтобы они прошли через `needs`)
2. SSH на VPS → `cd /opt/vibely-staging`
3. `git pull origin main`
4. `docker compose --env-file .env.staging pull`
5. `docker compose --env-file .env.staging up -d --build`
6. Health check: `curl -f https://staging.vibely.com/api/health`

---

## Workflow 3 — `deploy-prod.yml`

**Триггер:** push в `release`

**Шаги:**
1. SSH на VPS → `cd /opt/vibely`
2. `git pull origin release`
3. `docker compose pull`
4. `docker compose up -d --build`
5. Health check: `curl -f https://vibely.com/api/health`

Деплой в прод **не запускает lint/build** — release создаётся только из main, который уже прошёл проверки.

## Серверная часть (VPS)

### Структура на сервере

```
/opt/
├── vibely/           ← прод (origin/release)
│   ├── docker-compose.yml
│   └── .env          ← продовые секреты, не в git
└── vibely-staging/   ← стейджинг (origin/main)
    ├── docker-compose.yml
    └── .env.staging  ← стейджинговые секреты, не в git
```

### Nginx (уже должен быть настроен)

```nginx
# staging.vibely.com → порт 3100 (frontend staging)
# vibely.com         → порт 3000 (frontend prod)
```

В `docker-compose.yml` для staging нужны другие порты:
- frontend: `3100:3000`
- backend: `3101:3001`
- ai: `3108:8000`

### Деплой-пользователь на сервере

```bash
# Создать отдельного пользователя без sudo с доступом только к docker и /opt/vibely*
useradd -m deploy
usermod -aG docker deploy
```

## GitHub Secrets

Добавить в репозитории Settings → Secrets:

| Secret | Значение |
|--------|---------|
| `VPS_HOST` | IP сервера |
| `VPS_USER` | `deploy` |
| `VPS_SSH_KEY` | приватный SSH ключ deploy-пользователя |
| `VPS_STAGING_PATH` | `/opt/vibely-staging` |
| `VPS_PROD_PATH` | `/opt/vibely` |

---

## Защита веток (Branch Protection)

Настроить в GitHub → Settings → Branches:

**`main`:**
- Require PR before merging
- Require status checks: `frontend-lint`, `backend-lint`, `ai-lint`, `frontend-build`, `backend-build`
- Dismiss stale reviews on new push

**`release`:**
- Require PR before merging (merge только из `main`)
- No direct push (только через PR)

---

## Порядок реализации

1. Создать структуру директорий на VPS (`/opt/vibely-staging`, `/opt/vibely`)
2. Клонировать репо на сервер в обе папки
3. Настроить `.env` файлы на сервере
4. Создать deploy-пользователя и SSH ключ
5. Добавить secrets в GitHub
6. Написать `.github/workflows/ci.yml`
7. Написать `.github/workflows/deploy-staging.yml`
8. Написать `.github/workflows/deploy-prod.yml`
9. Настроить branch protection на `main` и `release`
10. Проверить: создать ветку `feature/test-ci`, сделать пуш → убедиться что CI запустился
